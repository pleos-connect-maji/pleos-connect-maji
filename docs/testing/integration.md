## 2. 테스트 환경

- 에뮬레이터: `Pleos_Connect_v2.1.0`, cold boot (`emulator -avd Pleos_Connect_v2.1.0 -no-snapshot-load`)
- 빌드: develop 디버그 빌드 (`./gradlew.bat :app:installDebug`)
- 탑승자 준비
  - `mom`: 기후 값 있음 (겨울 열선 1단계, 15℃)
  - `kid`: 기후 값 없음 (자리 설정이 떠야 함)
- Virtual Console (`http://127.0.0.1:8088`)을 열어 두고, `adb forward tcp:8088 tcp:8088`로 연결
  - 기어: `/vehicle/gear?gear=Drive|Park`
  - 문: FR(조수석 앞문) 토글
  - 열선·온도: 조수석 패널 또는 `/vehicle/state`로 확인
- 화면 조작: `uiautomator dump`로 버튼 좌표를 찾아 탭
- 음성은 사람이 직접 청취

### S7 상세 (재시작 복원)
- ✅ 맞이 중 `mom` 시작 → 준비 상태에서 앱 강제 종료 → 재실행: "mom 자리 맞추는 중… 열선 1단계, 15℃"와 최종 하차·맞이 취소 버튼이 복원됨
- ✅ 맞이 취소: 조수석 열선이 원래 값(Off)으로 복구됨
- ❌ 맞이 취소: 조수석 온도가 원래 값으로 돌아가지 않음 (준비 때 값 15℃ 유지)
  - 원인: 맞이 시작 때 원래 온도 값이 비어 있음 (에뮬레이터에서 온도 읽기 실패, 재시작 후에는 온도 신호도 오지 않음)
  - 확인 요청: #26 댓글 (근희: 온도 읽기 원인, 나경: 시작 때 온도 값 전달 가능 여부)

## 4. 진행 방법
1. 블로커(#86, #87, #26 온도)를 먼저 해결합니다.
2. S1 → S9 순서로 실행합니다. 각 단계마다 화면 문구를 확인하고, 필요하면 스크린샷과 logcat(`MajiDev` 등)을 남깁니다.
3. 결과는 이 문서의 "결과" 칸과 "비고"에 기록합니다 (통과 / 실패 / 부분 통과 / 미실행).
4. 실패는 이슈로 등록하고 담당자를 지정합니다. 고친 뒤 같은 시나리오를 다시 돌립니다.
5. 완료 기준: S1~S9 모두 통과, 블로커 해결.

## 5. 한계
- 실차가 아니라서 시트 위치는 확인할 수 없습니다. 에뮬레이터에서는 시트 이동 명령은 성공하지만 위치 값이 바뀌지 않습니다. 열선·온도·창문과 앱 상태 중심으로 봅니다.
- 음성 품질은 사람이 직접 들어야 합니다.
- 실차 확인이 필요한 항목(시트 위치, 온도 읽기)은 실차 테스트 때 따로 확인합니다.
