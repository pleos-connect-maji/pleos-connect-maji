# 맞이 흐름 (C. MajiFlow)

> 모듈: `flow` · 담당: C(윤우린) · 기준: develop 최신 상태
> 이 문서는 맞이 흐름의 동작과 다른 모듈과의 연결을 설명합니다. 동작이 바뀌면 함께 고칩니다.

## 한 줄 소개

차 신호(P단, 조수석 문)에 맞춰 탑승자를 위한 자리 준비, 인사, 귀갓길 설정, 원상복구를 순서대로 실행합니다.

## 파일 구성

| 파일 | 하는 일 |
|---|---|
| `flow/MajiFlowImpl.kt` | 단계 전환, 신호 처리, B·D·E 호출, 학습 기록 |
| `ui/StartScreen.kt` | 시작 화면: 프로필 버튼을 누르면 `start` |
| `ui/ProgressScreen.kt` | 진행 화면: 단계 문구, 최종 하차·맞이 취소 버튼 |
| `ui/SeatSetupScreen.kt` | 자리 설정 화면(원영 담당): 열선·온도·시트 조절 |
| `ui/SeatSetupRules.kt` | 자리 설정 화면을 띄울 조건 (`needsSeatSetup`) |
| `MainActivity.kt` | 흐름과 화면, 차 신호, 차 제어, 음성, 탑승자 저장소를 연결 |

## 단계별 동작

| 단계 | 들어가는 조건 | 흐름이 하는 일 |
|---|---|---|
| `IDLE` | 맞이 전 | - |
| `HEADING` | 시작 화면에서 탑승자 선택 (`start`) | 탑승자 설정 저장. 맞이 중이면 무시 |
| `PREPARING` | P단에 들어감 (`onParkChanged(true)`) | 원래 상태 읽기 → 오늘 계절 값으로 자리 준비 → 준비 안내음 → 끝나면 완료 안내음 |
| `BOARDED` | 준비 중에 조수석 문이 열림 | 시트 정지 → 인사 → 노래 → 오늘만의 인사 비우기 |
| `RIDING_HOME` | 탑승 뒤 P단을 해제 | 귀갓길 설정(창문, 무드등) |
| `FINISHED` | 최종 하차 (`finish`) 또는 취소 (`cancel`) | 복구 → 음성 정지 |

세부 규칙:
- **브레이크 신호는 쓰지 않습니다.** 나경의 신호에 주차 브레이크 이벤트가 없어서, P단만으로 준비를 시작합니다(PR #65).
- **준비 중 문 열림**: 자리 준비 중에 문이 열리면 바로 `BOARDED`로 갑니다. 준비가 끝나지 않아도 시트는 멈춥니다.
- **준비 완료 안내음**: 준비가 끝났을 때 아직 `PREPARING`이면만 재생합니다. 문이 먼저 열렸으면 재생하지 않습니다.
- **문 신호는 `BOARDED` 전에만 의미가 있습니다.** 귀갓길 중 문이 열리고 닫혀도 단계는 `RIDING_HOME`에 그대로 있습니다. 중간 하차로 보고 복구하지 않습니다(#25).
- **인사는 한 번만**: 인사가 끝나면 오늘만의 인사(`specialGreetingText`)를 비웁니다(#38). 맞이를 취소하면 인사가 끝나지 않으므로 비우지 않습니다.
- **원래 상태**: 준비 전에 B가 읽은 열선·온도·창문 값을 저장해 두었다가, 하차나 취소 때 되돌립니다. 온도는 에뮬레이터에서 읽히지 않아서, A가 알려 준 마지막 온도를 대신 씁니다.

## 학습 규칙 (`finish`에서만)

탑승자가 직접 바꾼 값만 그 계절에 저장합니다(#38, PR #61).

1. 준비할 때 보낸 값(`preparePassenger`의 `Climate`)을 기준으로 삼습니다.
2. 탑승 뒤(`BOARDED`, `RIDING_HOME`)에 A가 알려 주는 열선·온도가 기준과 다르면 기록합니다.
3. 기준 값으로 되돌리면 기록을 지웁니다.
4. 준비 값이 없는 계절(설정 안 한 계절)은 기준이 없어서 기록하지 않습니다.
5. 최종 하차(`finish`)에서만 저장합니다. 취소(`cancel`)는 저장하지 않습니다.

**한계**: 차가 자동으로 바꾼 값도 신호로 옵니다. 나경의 신호는 누가 바꿨는지 구분하지 않아서, 자동 변화를 완벽히 거를 수 없습니다. 준비 중 변화와 되돌림을 제외하는 방식으로 줄였습니다.

## 주행 상태 (화면에서 막기)

- 나경의 `onDrivingRestrictionChanged`는 **P단이 아니면 주행 중**으로 봅니다.
- 시작 버튼, 탑승자 관리 버튼, 진행 화면의 최종 하차·맞이 취소 버튼, 자리 설정 화면은 주행 중에 막습니다(화면에서만 막음).
- 흐름 자체는 주행 중에도 명령을 받습니다. 흐름 쪽 가드는 검토 후 취소했습니다.

## 대체 모드 (제어가 막힌 차)

- `control.isControlAvailable()`이 `false`이면 진행 화면 문구를 바꿉니다(근희 문구, PR #56).
  - 준비 중: "○○ 자리는 직접 맞춰 주세요" + 준비 값(열선·온도) 둘째 줄
  - 종료: "맞이가 끝났어요! 자리는 직접 원래대로 돌려 주세요!"
- 안내음과 탑승·귀갓길 문구는 그대로입니다.

## 앱 연결 (`MainActivity`)

- **차 제어는 하나만** 만들어서 흐름과 화면이 같이 씁니다(시트 기록이 하나로 유지). 화면을 나갈 때 `release()`를 부릅니다.
- **음성**: `PleosGreeter.create(context)`로 만듭니다.
- **탑승자 저장소**: `RoomProfileRepository.create(context)`로 실제 DB를 씁니다.
- **차 신호**: `PleosVehicleSignals`를 켜서, 신호를 흐름에 그대로 넘기고 주행 상태와 자리 설정에 쓸 값을 따로 기억합니다. 화면을 나갈 때 멈춥니다.
- **코루틴 범위**: 흐름이 저장(suspend)을 부를 때 씁니다.

## 화면 흐름

- **홈**: 맞이가 시작되면 위쪽에 진행 화면이 나타나고, 아래쪽에 시작 화면(탑승자 버튼)이 있습니다.
- **탑승자 관리**: 홈의 "탑승자 관리" 버튼에서 목록, 추가, 수정 화면으로 갑니다(원영 담당).
- **자리 설정**: 조건(`needsSeatSetup`)이 맞으면 홈 대신 자리 설정 화면을 띄웁니다. 현재 `MainActivity`에는 아직 연결되어 있지 않습니다(원영 확인 대기, PR #72).

## 열린 것

1. **자리 설정 화면 띄우는 조건** (원영 확인 대기, PR #72): 띄우는 시점(P단 기준), 주행 중 잠금 기준, 문 조건, 계절 값 기준. 조건이 정해지면 `SeatSetupRules.kt`의 `needsSeatSetup`만 고칩니다.
2. **하차 확인 다이얼로그**: 최종 하차를 누르면 확인을 묻고, "예"일 때 `finish`를 부르는 화면이 필요합니다(원영 요청).
3. **시작 화면과 탑승자 관리 합치기**: 원영과 방식을 정해야 합니다.
4. **앱 재시작 후 단계 복원과 백그라운드 동작 (#26)**: 저장 방식과 서비스 방식을 정해야 합니다. PT 이후 일정입니다.
5. **내비 목적지 설정 (#27)**: NaviHelper SDK 조사부터 합니다. 우선순위가 낮습니다.
6. **무드등 시점**: 귀갓길 시작 때 바꿀지, 정차 중 문이 닫힐 때 바꿀지 정해야 합니다.
7. **계절 기준**: 4~10월은 여름, 11~3월은 겨울로 날짜로 정합니다. 바꿀지 확인이 필요합니다.

## 에뮬레이터에서 확인하는 방법

1. 에뮬레이터(`Pleos_Connect_v2.1.0`)를 cold boot로 켭니다.
2. `adb forward tcp:8088 tcp:8088`으로 Virtual Console을 연결하고, 브라우저에서 `http://127.0.0.1:8088`을 엽니다.
3. 앱에서 탑승자를 누르면 `HEADING`이 됩니다. 기어를 P로 바꾸면 `PREPARING`이 되고, 조수석 문(FR)을 열면 `BOARDED`가 됩니다.
4. 기어를 D로 바꾸면 주행 중으로 보고 버튼이 막힙니다. P로 돌아오면 다시 누를 수 있습니다.
5. 확인이 끝나면 `adb forward --remove tcp:8088`과 `adb emu kill`로 정리합니다.

에뮬레이터에서는 시트 위치가 바뀌지 않습니다. 열선과 온도로 확인합니다.
